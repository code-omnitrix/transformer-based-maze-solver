### Inferences

- The reduction in training loss as well as held-out token error is compatible with improved optimization or computation, rather than only reduced overfitting. Training loss uses dropout and validation accuracy is a different statistic, so these curves do not by themselves quantify a train-validation generalization gap.
- With the same batches, 6 rather than4 calls per encoder/decoder means about1.5 times as many block applications per example. Thirty looped epochs correspond to about45 four-layer epochs by that crude count, compared with90 baseline epochs. This is **not** a wall-clock or FLOP measurement; dropout, attention shapes, padding, norm placement, initialization and implementation can change the true ratio.
- The final model loss cannot identify which intervention caused its gain. Tying may supply an iterative bias, but pre-LN stability and input anchoring are equally testable explanations.

### Gaps

- Historical weights, per-example predictions, exact dataset snapshot, optimizer/RNG state, package versions and timings were not saved in the original notebook. We cannot re-evaluate those final historical weights, compute paired error tests on their predictions, or recover their exact historical dataset from logs alone.

## What does accuracy measure, and is data leakage the explanation?

### Takeaway
The notebook correctly excludes PAD labels and uses a causal decoder mask. Its accuracy measures next-token prediction **conditioned on the correct path prefix**, including EOS. It does not measure whole-maze autonomous planning success. A fresh replay shows no exact-grid overlap, but it does not certify the inaccessible historical arrays.

### Cited findings

- At target position`t`, shifted input contains BOS and true actions before`t`; labels contain action`t` or EOS. A strict upper triangular boolean mask blocks future target positions. Looped decoder applies this mask on every recurrence; its encoder sees only maze input. No direct target leakage is visible in the code. [Notebook cells2,3,5,6.]
- Accuracy is `sum(pred[mask] == label[mask]) / sum(mask)` with `mask = labels != PAD`. BOS is not a label; EOS is. There is no padding-inflation bug. [Notebook cells3,6.]
- The maze generator samples independent random walls at probability0.28, overwrites distinct start/goal cells, then rejects unsolvable mazes and shortest paths shorter than4. The resulting conditional dataset is **not** an unconditioned Bernoulli-wall distribution. BFS explores U,L,R,D in a fixed order, so its chosen shortest-path string has a canonical directional tie bias. [Notebook cell1.]
- New isolated replay of the saved generator with Python/NumPy seeds42 generated50,000 unique training grids and5,000 unique validation grids, with zero grid overlap. Validation mean shortest path7.3806 moves, range4–24. It has41,903 non-PAD labels, including5,000 EOS tokens (11.9323%). The hypothetical PAD fraction would be66.4776% if padding were counted; it is not. [independent_statistics.py/json.]
- Replayed train grid-array SHA256 is`e96405517a4c74fa62df0a11856ae7ded028d760c783e37e51308241a2e4f03d`; validation`ec3898d0282f17005d1fb8c079d5cef7637ea7a11ed07dba67942831c52bc6af`. Grids are cast to uint8 before hashing. This is a **new deterministic code replay**, not a recovered historical dataset. [independent_statistics.json.]
- On the fresh5,000-maze replay,74.72% of mazes have multiple shortest paths. Canonical string accuracy can therefore reject a valid shortest route. BFS route counting counts all shortest valid routes using distance-layer dynamic programming. [independent_statistics.py, independent_baselines.csv.]
- A new no-training baseline chooses the valid neighbor with smallest Manhattan distance, breaks ties U,L,R,D, and emits EOS upon reaching the goal. On the replay it obtains86.5570% teacher-forced token accuracy but58.32% autonomous goal success,55.60% shortest-route success, and53.66% canonical exact accuracy, with a40-move cap. This concretely demonstrates that a high token metric can coexist with substantially lower task success **for this heuristic**; it does not estimate either trained model's rollout success. [independent_baselines.csv; independent_statistics.json.]
- A BFS oracle reproduces the canonical labels and shortest route by construction, so its100% correctness is a sanity check, not a neural learning result. [Saved generator and independent_statistics.py.]

### Inferences

- EOS is about12% of replay target tokens; predicting termination correctly can raise aggregate token accuracy. Report action-only accuracy, EOS precision/recall and early-EOS frequency separately. Their historical values are unknown.
- The wall-aware greedy baseline and canonical path tie bias make wall-avoiding local heuristics plausible shortcuts. Stronger evidence of planning would require success on detours, long paths and changed wall densities, where Manhattan greed fails.
- Different mazes are the natural resampling units; tokens within a maze are correlated. For a paired model comparison bootstrap maze IDs with both models' predictions together. Separately repeat training over initialization/data seeds. A naive binomial CI over41,903 tokens does not measure training variability.
- First-token accuracy isolates decisions without a supplied true path prefix. Autonomous shortest-path success measures the task. Report both, plus token accuracy, invalid-move rate, premature stopping, no-EOS, and path-length-conditioned performance.

### Gaps

- No aggregate autoregressive accuracy is saved: the notebook displays only4 baseline and8 looped examples. This small visual sample cannot estimate success.
- The plotting helper silently skips non-directional predicted symbols while tracing, rather than scoring them as illegal. Strict future evaluation should log PAD/BOS and invalid moves explicitly; reaching goal without EOS should be a separate outcome.
- The40-step rollout cap can exclude rare paths longer than40, although fresh replay maximum24 fits it. Increase the cap and decoder position capacity consistently for harder distributions.

## Which outcomes would explain or falsify the proposed mechanisms?

### Takeaway
The following interpretation rules were specified **before new training results were available**. They distinguish local explanations from universal claims; a mechanism can coexist with others.

### Cited findings

These are proposed causal tests motivated by the audited code above, not observed results. The actual experiment configuration must be read from the run manifest before interpreting them.

| Hypothesis | Discriminating comparison | Predicted signature | What would weaken it |
|---|---|---|---|
| Pre-LN optimization explains most of the gain | untied post-LN vs pre-LN, same depth/init/anchor | pre-LN improves loss and success; tying adds little afterward | matched pre-LN does not close gap |
| More effective depth explains the gain | untied4 vs untied6 with other settings fixed | untied6 closes looped advantage at similar compute | tied6 still better under budget matching |
| Initial-input anchoring preserves task state | tied6 anchor vs no anchor | anchor improves detour/long-path success and later-loop state usefulness | no effect across seeds and difficulty bins |
| Loop encoding permits stage-specific computation | tied6 with/without iteration signal | consistent useful gain and distinct stage dynamics | similar results or no-encoding better |
| Weight tying supplies useful iterative inductive bias | tied6 vs untied6 with same pre-LN/anchor/encoding/init | tied improves held-out/OOD metrics, especially under small data | untied matches or wins across paired seeds |
| Smaller unique parameter count regularizes | compare tied6 against parameter-matched untied model, plus data scaling | benefit largest at low data, diminishes with more data | benefit persists independent of data/parameter budget |
| Loop advantage reflects learned iterative planning | same checkpoint evaluate K=1,2,4,6,8,12 and detours | useful depth-difficulty interaction; rollout improves toward trainedK | teacher-forced gain only, or excessK consistently harms |
| Simple shortcuts dominate evaluation | obstacle/detour and path-length stratification; first-token and rollout metrics | disproportionately poor hard-bin success despite high aggregate token score | robust success across controlled hard bins |

### Inferences

- Test-timeK extrapolation is not guaranteed by sinusoidal index encoding. Hidden states can leave their training distribution, especially under repeated anchoring and unnormalized residual accumulation. A failure beyond6 loops does not falsify recurrence's benefit at trained depth.
- If input anchoring or pre-LN explains the effect, that is a useful architectural finding even if tying itself is neutral.
- Width/depth/parameters/data/optimizer steps/wall-clock/FLOPs cannot generally all be matched simultaneously. Label each comparison by its actual budget, and report a compute-performance frontier instead of implying one universally fair scalar match.

### Gaps

- These planned tests cannot establish exact BFS implementation in network weights. Behavioral success, representational probes and interventions can strengthen the iterative-planning interpretation, but mechanistic identity needs more evidence.
